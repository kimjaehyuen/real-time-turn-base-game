# 실시간 턴제 전투 데모

TypeScript + Vite로 만든, "실시간 턴제(Real-Time Turn-Based)" 전투 시스템 데모입니다.

## 실행 방법

```bash
npm install
npm run dev
```

브라우저에서 안내되는 로컬 주소로 접속하면 됩니다. `npm run build`로 정적 빌드도 가능합니다.

## 데스크톱 실행파일(.exe)로 빌드하기

Electron으로 감싸서 Windows용 실행파일을 만들 수 있습니다.

**방법 A: GitHub Actions에서 빌드 (Windows PC가 없어도 됨, 권장)**

이 저장소의 GitHub → Actions 탭에서 **"Build Windows executable"** 워크플로를 수동 실행(`Run workflow`)하면,
실제 Windows 러너에서 빌드한 뒤 완료된 실행파일을 워크플로 실행 결과의 Artifacts에서 zip으로 내려받을 수 있습니다.
(`v`로 시작하는 태그를 푸시해도 자동으로 실행됩니다.)

**방법 B: 로컬 Windows PC에서 직접 빌드**

```bash
npm install
npm run dist:win
```

`release/` 폴더에 설치형 실행파일(`TurnBattleDemo Setup x.x.x.exe`)과 별도 설치 없이 바로 실행되는
포터블 실행파일이 생성됩니다. (서명이 되어있지 않아 Windows SmartScreen 경고가 뜰 수 있는데, "추가 정보 → 실행"으로 진행하면 됩니다.)

> 참고: `dist:win`은 Windows용 빌드 도구(NSIS 등)를 사용하므로 macOS/Linux에서 실행하려면 별도로 `wine`이 설치돼 있어야 합니다.
> Windows PC에서 직접 실행하거나, 위 방법 A(GitHub Actions)를 사용하는 쪽이 훨씬 간단합니다.

개발 중 Electron 창으로 미리 보고 싶다면(핫리로드 포함): `npm run electron:dev`

## 핵심 규칙과 구현 위치

1. **턴이 활성화되어도 다른 캐릭터의 진행이 멈추지 않는다.**
   `src/engine/battle.ts`의 `chargeGauges()`가 매 프레임 살아있는 모든 캐릭터의 ATB 게이지를 충전합니다.
   이미 "준비 상태"인 캐릭터만 충전을 멈추고, 그 외에는 누군가 행동을 고르고 있어도 계속 시간이 흐릅니다.

2. **먼저 턴이 활성화된 캐릭터가 있어도, 나중에 활성화된 캐릭터가 먼저 행동할 수 있다.**
   게이지가 가득 찬 캐릭터는 모두 `readyIds`에 들어가 동시에 "행동 가능" 상태가 되며, 순서가 실제 행동 순서를
   강제하지 않습니다. 플레이어 캐릭터는 준비된 순서와 무관하게 원하는 아무 캐릭터부터 행동시킬 수 있고
   (하단 액션 패널에 준비된 아군 전원이 각자 버튼과 함께 나열됩니다), 적은 캐릭터마다 독립적인 "생각 시간"
   타이머로 따로따로 행동합니다. 그래서 리엘이 먼저 준비되어 있어도, 그 사이 플레이어가 입력을 미루면
   나중에 준비된 다크 샤먼이 먼저 공격할 수 있습니다.

3. **캐릭터마다 고유한 일반공격/스킬/필살기가 있고, 필살기는 자기 턴이 아니어도 사용 가능하다.**
   `src/engine/characters.ts`에 5명(전사/마도사/힐러 + 적 2종)의 스킬셋이 정의되어 있습니다.
   `performUltimate()`는 `readyIds`를 전혀 건드리지 않는 별도 경로로, 에너지가 가득 차면 즉시 발동합니다 —
   화면에서도 각 캐릭터 카드의 필살기 버튼으로 언제든(내 턴이 아니어도) 사용할 수 있습니다.

4. **캐릭터마다 속도(SPD)가 달라 턴이 열리는 주기가 다르다.**
   게이지 충전 속도는 `effectiveSpd(character)`에 비례합니다 (속도 버프/디버프도 반영).

5. **버프/디버프 지속시간은 턴 수 또는 실제 시간(초)으로 계산될 수 있다.**
   `src/engine/types.ts`의 `StatusTemplate.durationType`이 `'turn' | 'time'`을 구분합니다.
   - `turn` 기반 효과(예: 전사의 철벽, 오크의 분노)는 효과를 가진 캐릭터 자신의 턴이 끝날 때만 1씩 감소합니다.
   - `time` 기반 효과(예: 화상, 중독, 재생)는 턴과 무관하게 실제 경과 시간(ms)에 따라 계속 감소하며, 일정 간격마다 도트 피해/회복을 발생시킵니다.

6. **스킬은 아군 전체가 공유하는 SP(스킬 포인트)를 소모한다.**
   `BattleEngine.sp` / `maxSp`(10)가 아군 전체가 공유하는 자원입니다 (적은 관여하지 않습니다).
   일반공격은 보통 SP를 1 회복시키고, 스킬은 캐릭터마다 정해진 만큼 소모합니다 — 대부분 1이지만
   화염 마도사 리엘의 "화염구"(전체 공격)처럼 2를 쓰는 스킬도, 암살자 카인의 "그림자 일격"처럼
   0을 쓰는(=항상 즉시 사용 가능한) 스킬도 있습니다. 성기사 세라의 필살기 "천사의 축복"처럼
   일부 캐릭터는 필살기로도 SP를 회복시킵니다 (`SkillDef.spCost` / `spGain`, `src/engine/characters.ts`).
   SP가 부족하면 스킬 버튼이 비활성화됩니다.

7. **대상을 선택하는 동안에는 게이지와 지속시간 있는 버프/디버프까지 전부 멈춘다.**
   스킬(혹은 일반공격/필살기)의 대상을 고르는 중에는 `BattleEngine.setTargetSelectionPaused(true)`가 호출되어
   아군/적 가릴 것 없이 게이지 충전, 적 AI의 행동 진행, 그리고 턴 기반이든 시간 기반이든 모든 버프/디버프의
   지속시간 감소(화상·중독 같은 도트 틱 포함)까지 전부 멈춥니다 — 대상을 고르는 동안에는 전황이 조금도
   바뀌지 않습니다. (단, 필살기는 이 정지와도 무관하게 계속 즉시 사용 가능합니다.)

8. **아군은 최대 4명, 적은 최대 5마리까지 동시에 편성될 수 있다.**
   파티 편성 화면에서 최대 4명까지 고를 수 있고, 적은 이 데모에서 고정 편성인 5마리가 항상 등장합니다
   (`src/engine/characters.ts`의 `PLAYER_CHARACTER_DEFS` / `createBattleRoster()`).

9. **필살기는 키보드로도 사용할 수 있다.**
   캐릭터/대상 선택은 항상 마우스로 하고 (준비된 아군 카드를 클릭하면 선택되어 `Q`=일반공격,
   `E`=스킬로 행동을 고를 수 있습니다), `1`~`4`(카드 우측 상단의 번호와 대응)는 그 슬롯의 필살기가
   준비되어 있을 때만 즉시 사용하는 단축키입니다 (`src/main.ts`의 keydown 핸들러). 준비되면 카드의
   번호 배지가 보라색으로 강조됩니다.

10. **피해량은 화면 좌/우에 숫자로만 표시되고, 그 편이 다시 행동할 때마다 초기화된다.**
    전투 로그 대신, 아군이 적에게 입힌 피해는 화면 우상단에, 적이 아군에게 입힌 피해는 좌하단에
    숫자만으로 표시됩니다. 한쪽이 새 행동(일반공격/스킬/필살기)을 시작하면 그 편의 표시만 0으로
    리셋된 뒤 이번 행동의 피해량으로 다시 채워집니다 — 즉 누적 총합이 아니라 "가장 최근 행동의
    피해량"입니다 (`BattleEngine.lastPlayerDamage` / `lastEnemyDamage`).

11. **타이틀 → 파티 편성 → 스테이지 → 전투 순서로 진행된다.**
    게임은 "Real - Time" 타이틀 화면에서 시작합니다. "게임 시작"을 누르면 파티 편성 화면으로
    이동해 아군 캐릭터들의 상세 스펙(공격력/체력/방어력/속도)과 일반공격·스킬·필살기의 이름 및
    효과를 확인하고 최소 1명(최대 4명)을 선택해야 "전투 시작" 버튼이 활성화됩니다. 전투 시작을
    누르면 화면 정중앙에 스테이지 이름이 잠시 표시된 뒤(전투 화면에서는 보이지 않음) 실제 전투로
    넘어갑니다 (`src/main.ts`의 화면 상태 머신, `src/ui/partyScreen.ts`).

12. **공격 범위(단일/범위/전체) · 피해 종류(물리/마법) · 속성(7종) · 내성으로 세부 피해가 계산된다.**
    `src/engine/damage.ts`의 `computeDamage()`가 아래 공식을 그대로 구현합니다.

    ```
    ((공격력*계수)+피해량증가)
      * (1+물리|마법 피해증가+속성 피해증가+전체 피해증가)
      * (최종 피해증가)
      * (1-(적 물리|마법 내성+적 속성 내성))
      * (1+적이 받는 물리|마법 피해증가+받는 속성 피해증가+받는 피해증가)
      * (치명타)
      * (적 방어력 계수)
    ```

    - **공격 범위**: `TargetType`에 `singleEnemy`(단일, 주 목표 1명) / `areaEnemy`(범위, 주 목표 +
      원래 진형에서 바로 좌우에 있는 대상까지) / `allEnemies`(전체)가 있습니다 (아군 대상도 동일하게
      `singleAlly`/`areaAlly`/`allAllies`). "인접"은 화면에 표시되는 고정된 진형 순서를 기준으로
      계산되며 죽은 자리는 건너뜁니다 (`BattleEngine.adjacentGroup()`). 다크엘프 궁수의 "관통 사격"이
      범위 공격의 예시입니다.
    - **피해 종류(물리/마법)**: 스킬마다 정해져 있고(`SkillDef`를 만드는 각 함수 안의 `dmgType`),
      적의 물리 내성 또는 마법 내성 중 해당하는 쪽만 적용됩니다.
    - **속성(화염/얼음/번개/바람/바위/어둠/광휘)**: 캐릭터마다 고정으로 하나씩 가지고 있고
      (`Character.element`), 그 캐릭터가 가하는 모든 피해에 그대로 적용됩니다. 지속피해(도트)도
      물리/마법 구분 없이 속성만 적용됩니다 (예: 화상 = 화염, 중독 = 어둠 — `StatusTemplate.tick.element`).
    - **내성**: 적마다 물리/마법 내성(%)과 속성별 내성(%)을 가지고 있고(`Character.resistances`),
      물리|마법 내성과 속성 내성은 합연산으로 더해져 한 번에 경감됩니다.
    - **적 방어력 계수**: 방어력이 오를수록 받는 피해가 줄지만 0으로 수렴할 뿐 완전히 무효화되지는
      않는 체감형 곡선(`100/(100+방어력)`)을 사용합니다.
    - **치명타**: 캐릭터마다 기본 확률/배율(`Character.base.critRate`/`critDamage`)이 있고, 지속피해는
      치명타가 발생하지 않습니다.
    - 공식에서 "최종 피해증가" 항이 두 번 곱해지는 것으로 보일 수 있는데, 같은 배율을 두 번 곱하면
      사실상 제곱이 되어버려 한 번만 적용하도록 정리했습니다(`finalDmgIncrease`). 필요하면 서로 다른
      두 배율로 분리할 수 있습니다.
    - 피해량 증가(고정치 가산, `flatBonus`)와 각 피해증가/받는피해증가 항들은 아직 이 값을 부여하는
      버프가 없어 항상 0이지만, `StatModifiers`에 필드가 이미 준비되어 있어 나중에 장비나 버프로
      쉽게 연결할 수 있습니다.

## 구조

```
src/
  engine/
    types.ts          타입 정의
    statusEffects.ts  버프/디버프 템플릿 + 스탯 보정 계산
    damage.ts          공격 범위/물리·마법/속성/내성/치명타/방어력 계수를 포함한 최종 피해 공식(computeDamage)
    characters.ts      캐릭터 9종(편성 가능 아군 4 + 고정 적 5)의 스펙/속성/내성/일반공격·스킬·필살기 정의
    battle.ts          게이지/필살기 인터럽트/AI/공유 SP/피해량 카운터를 포함한 전투 시뮬레이션 엔진

    types.ts           UI 전용 타입 (대상 선택 상태 등)
    render.ts           전투 화면 DOM 렌더링 (구조 변경과 수치 갱신을 분리해 매 프레임 버튼이 재생성되지 않도록 함)
    partyScreen.ts       파티 편성 화면의 캐릭터 카드 그리드 렌더링
  main.ts               화면 상태 머신(타이틀/파티편성/스테이지/전투) + 게임 루프(rAF) + 이벤트 연결
  style.css
electron/
  main.cjs               Electron 메인 프로세스 (개발 중엔 vite dev 서버, 빌드 후엔 dist/index.html 로드)
.github/workflows/
  build-windows.yml       GitHub Actions에서 Windows 실행파일을 빌드하는 워크플로
```

## 조작

- 타이틀 화면에서 "게임 시작" → 파티 편성 화면에서 캐릭터 카드를 클릭해 최소 1명 선택 → "전투 시작"
- 전투 중: 턴이 활성화된 아군 카드를 클릭해 선택 → `Q` 일반공격 / `E` 스킬 (또는 액션 패널 버튼 클릭),
  대상이 필요하면 대상 카드를 클릭
- 필살기: 카드 아래 버튼(에너지가 가득 차면 언제든 사용 가능) 또는 키보드 `1`~`4` (카드 번호와 대응)
- 상단 컨트롤: 일시정지, 배속(x1/x2/x4), 전투 재시작
- 상단 SP 바: 아군이 공유하는 스킬 포인트 (최대 10)
- 화면 우상단: 아군이 적에게 입힌 최근 피해량 / 좌하단: 적이 아군에게 입힌 최근 피해량 (숫자만 표시)
